# Synchronization protocol

Local commits happen first and set `dirty=true`. Each record coalesces pending edits; physical deletion is replaced by a dirty tombstone. SQLite/IndexedDB persist that outbox across restart. Auth state triggers sync; edits debounce 1.5 seconds; reconnect, window focus and the explicit Sync button trigger another attempt. Failures retry with exponential backoff from 1 second to 5 minutes while auth remains active. Sign-out cancels scheduled retries.

Pushes are ordered so parent projects/habits/contacts precede dependent records. Recurrence templates precede occurrences, and focus sessions precede their reminders. `lifeos_push` locks one owner-scoped row, compares expected remote version and either returns a new revision or the current conflicting row. Repeating the identical payload is an idempotent acknowledgement. No timestamp last-writer-wins merge is used. A local edit during the network operation prevents the acknowledgement CAS; its dirty state remains and is retried.

Pulls are paginated, ordered by stable UUID, validated and merged only into clean records. Dirty records with a different remote version become conflicts. Both versions stay available in the conflict UI; choosing a version first downloads a JSON conflict backup. Keeping local rebases its expected cloud version and pushes on the next attempt; keeping cloud replaces only the chosen record. Tombstones prevent ordinary offline resurrection. There is no hard-delete compaction yet.

Settings are device-local. A local owner binding blocks accidental mixing of two cloud accounts. Use another browser/OS profile for another owner. Failed references or malformed server records stop sync without silently discarding local changes. The last successful sync time is session-local display state; durable per-device sync metadata and incremental remote cursors are not implemented. Full paginated pulls occur on sync triggers, not a constant polling loop. A tab left idle does not receive remote updates until the next trigger; Realtime remains future work.

Known distributed edge: edits during paginated reads converge on the next sync rather than a snapshot-isolated bulk transaction. A complex cross-record graph import can require dependency repair; the UI reports an error rather than silently dropping links. Browser clock skew affects display timestamps but never determines conflict ownership. All scheduling instants are UTC, and recurrence templates store their IANA timezone separately.

Recurrence policy: generate the next 35 calendar days (hard ceiling 93), keep existing occurrences independent, keep missed existing occurrences open/overdue, and do not backfill an unbounded past. Monthly dates clamp to the last day of a shorter month. Templates retain their own timezone even if the display timezone changes. Nonexistent spring-forward wall times are rejected in manual scheduling and skipped during recurrence generation; repeated fall-back wall times choose the first instant. These policies are unit-tested, including DST offset changes. Editing a template does not overwrite existing occurrences; edit existing occurrences individually.
