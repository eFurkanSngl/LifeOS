# Setup

## Local tools

Install Node 24 and pnpm 11.25.0, then `pnpm install --frozen-lockfile`. `pnpm dev` starts Next.js at http://127.0.0.1:3000. No cloud account is required. `pnpm dev:desktop` is a browser preview, not a native reminder process.

For Windows Tauri install current stable Rust (MSVC toolchain), Visual Studio Build Tools with **Desktop development with C++**, **MSVC x64/x86 build tools** and **Windows 10/11 SDK**, and Microsoft Edge WebView2 Runtime. In this workspace Rust 1.99.1 was installed only under `.tools`; the Visual Studio installer exists but the C++ linker is missing. The actual cargo check stopped at `link.exe not found`, so native typechecking, native tests, and installer validation are not passed. Install the missing C++ workload through Visual Studio Installer, then use a Developer PowerShell/terminal. To reuse this workspace's local Rust without a global install, run `$env:CARGO_HOME=(Join-Path (Get-Location) '.tools/cargo')`, `$env:RUSTUP_HOME=(Join-Path (Get-Location) '.tools/rustup')`, and `$env:PATH="$env:CARGO_HOME\bin;$env:PATH"` in the current PowerShell session. This does not modify the system PATH. Open a new terminal and verify `rustc --version` and `cargo --version`. Then:

```powershell
pnpm desktop
pnpm --filter @lifeos/desktop tauri build
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

The installer is generated under `apps/desktop/src-tauri/target/release/bundle/nsis`. Unsigned installers can trigger SmartScreen; no signing certificate is configured. The builder never silently enables startup or tray persistence.

## Supabase

Use a dedicated private project. Keep service-role/secret keys out of clients and out of chat. Create your single owner in Auth admin, disable public signup and anonymous sign-in, and configure production email delivery. Update the email OTP template to show `{{ .Token }}`; the app uses code entry with `shouldCreateUser:false`, not public signup or a magic-link redirect.

The initial migration is already present at `supabase/migrations/20261105193417_initial_lifeos.sql`, generated by official CLI 2.108.0. No live database was changed. With an installed Supabase CLI (or this environment's `.tools/supabase/package/bin/supabase.exe`), inspect the target before applying:

```powershell
supabase --help
supabase link --help
supabase link --project-ref YOUR_PROJECT_REF
supabase db push --help
# Review the target project and migration before applying:
supabase db push
```

For later schema changes, run `supabase migration new descriptive_change` and write an additive migration. The canonical schema is documented in `supabase/schema.sql`; it is not a replacement for migration history.

Do not repeat the CREATE schema on an existing deployment. Generate additive migrations for later changes. Enable the Data API for the public schema; the schema explicitly grants authenticated SELECT/INSERT/UPDATE and RPC execution with RLS. Run Supabase security advisors after applying. No anonymous access should be granted.

For web copy the two NEXT_PUBLIC entries from `.env.example` into `apps/web/.env.local`. For native copy the two VITE entries into `apps/desktop/.env.local`. Use the project HTTPS URL and publishable key only. Both are public client configuration. Restart development/build after changing environment values. Desktop sessions use Windows Credential Manager; web sessions last within the browser tab session. Do not switch cloud owners inside one local profile.

Live acceptance: sign in by code, create a project and scheduled task on web, sync, open native and sign in to the same account, sync, disconnect network, edit on desktop, edit the same record on web, reconnect and verify both conflict versions, choose one, sync and verify both clients converge. Complete a task and verify its reminder state. Test sign-out, expired tokens, unrelated-user access and offline restart. These live checks remain required even when local SQL tests pass.

## Vercel (instructions only)

Import your authorized private Git repository. Set root directory to `apps/web`, framework Next.js, Node 24, and include source files outside the root directory for workspace imports. Build from the workspace using pnpm; if overriding commands use `cd ../.. && pnpm install --frozen-lockfile` and `cd ../.. && pnpm --filter @lifeos/web build`, with output `.next` relative to `apps/web`. Set only NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY as client config. Set NEXT_TELEMETRY_DISABLED=1 and TURBO_TELEMETRY_DISABLED=1 if desired. Deploy a preview first and repeat the live acceptance checks. No deployment has been performed.

## Backups

Settings → JSON yedek indir exports private structured data. Store it in a location you control, ideally encrypted. Import checks schema version and skips existing IDs; it does not replace current records. To restore into an empty installation, export the original first, close desktop/MCP, preserve the original database files including WAL, and import into a new profile or installation. Never overwrite a running SQLite database with an external copy. Native audit/history tables are not included in JSON exports.
